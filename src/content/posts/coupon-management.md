쿠폰은 만들기보다 **겹쳐 눌렀을 때** 맞게 동작하게 하는 쪽이 어렵습니다. 같은 코드를 두 탭에서 동시에 등록하고, 발급 한도가 1장 남았을 때 두 사람이 받고, 쿠폰을 쓰는 순간 관리자가 일시중지하는 일이 모두 일어날 수 있습니다.

## 쿠폰의 모양

- 종류: 정액, 정률, 무료배송
- 받는 방법: 코드 등록, 쿠폰함에서 받기, 관리자 직접 발급, 자동(2단계)
- 대상: 전체, 카테고리, 기획전, 상품
- 기간: 고정 기간, 또는 발급일부터 N일

회원이 가진 쿠폰은 `UNUSED / USED / REVOKED`만 저장하고, **만료는 저장하지 않고 만료일로 계산**합니다. 만료를 처리하는 배치가 없어도 상태가 틀어질 일이 없습니다.

## 잠그는 순서와 조건부 UPDATE

MariaDB(InnoDB)는 트랜잭션이 시작된 뒤 다른 트랜잭션이 바꾼 행을 읽고 수정하려 하면 `Record has changed since last read` 오류를 냅니다. 그래서 읽기 전에 **회원 행, 쿠폰 행 순서로 `FOR UPDATE`** 잠금을 먼저 잡습니다. 순서를 고정해야 교착도 없습니다. 주문 생성도 회원 행을 먼저 잠그므로 같은 규칙입니다.

값을 바꾸는 쪽은 조건부 UPDATE로 한 번 더 막습니다.

- 발급 수 증가: 한도 미만일 때만 `issued + 1`
- 사용 처리: 상태가 `UNUSED`이고 만료 전일 때만 `USED`
- 취소 복구: 그 주문으로 쓴 쿠폰이고 만료 전일 때만 `UNUSED`

영향 행이 0이면 졌다는 뜻이므로 오류로 돌려줍니다. 동시성 테스트는 같은 코드 동시 등록, 마지막 한 장 동시 받기, 일시중지와 받기가 겹치는 경우를 실제 스레드로 돌립니다.

## 코드 입력 시도 제한

코드 등록은 추측 공격을 막으려고 10분에 10번으로 제한합니다. 실패만이 아니라 **모든 시도**를 셉니다. 이 카운트는 등록 트랜잭션이 롤백되어도 남아야 해서, 등록 메서드를 트랜잭션 밖에서 시작하고 제한 기록만 먼저 커밋한 뒤 본 작업을 `TransactionTemplate`으로 실행합니다.

## 주문과 엮기

- 견적과 주문에 `couponDiscount`, `memberCouponId`가 들어가고, 합계는 상품 + 대행 수수료 + 배송비 − 할인입니다. 대행 수수료는 **할인 전 상품 금액** 기준입니다.
- 쿠폰은 주문을 만들 때 사용 처리합니다. 결제 전에 다른 주문에 또 쓰이는 일을 막기 위해서입니다.
- 주문 취소(고객, 관리자)는 쿠폰이 아직 유효기간 안이면 되돌려 줍니다.
- 할인은 결제 금액이 **최소 1**이 되도록 제한합니다. 0원 결제가 결제 수단에서 어떻게 처리될지 정해지지 않았기 때문입니다.
- 쿠폰 이름은 주문에 4개 언어로 복사해 두어서, 쿠폰을 고치거나 지워도 지난 주문 화면이 변하지 않습니다.

## 리뷰에서 나온 것

마지막 리뷰에서 결제 화면에서 쿠폰을 바꿀 때 이전 견적 응답이 늦게 도착해 **금액이 화면과 서버가 다르게** 보이는 문제(요청 순번을 두고 가장 마지막 응답만 반영), 수정 모달에서 언어별 이름이 비어 있으면 깨지는 문제, 수정·일시중지·삭제가 행 잠금 없이 진행되던 문제를 고쳤습니다.
