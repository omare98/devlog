앱은 쇼핑몰 화면을 서버에서 불러오는 껍데기입니다. 로그인이 쿠키 세션이라 화면을 앱 안에 담을 수 없어서 그렇게 만들었습니다. 지금까지 APK는 제 PC에서 빌드한 파일을 직접 옮겨 설치했습니다. 이걸 GitHub에서 내려받아 설치하게 바꿨습니다. README의 "앱 받기" 링크 한 줄이 가장 최근 릴리스의 파일을 가리킵니다.

## 어떻게 동작하나

GitHub Actions 워크플로(`app-release.yml`)가 APK를 빌드해 릴리스에 `HuyaShop.apk`로 올립니다. 태그 `app-v0.1.0`을 push하거나, Actions 탭에서 버전을 넣어 직접 실행하면 됩니다. 파일 이름을 항상 같게 올리기 때문에 `releases/latest/download/HuyaShop.apk`라는 고정 주소가 생깁니다.

- **버전 이름**은 태그에서 가져옵니다. `0.1.0` 같은 형식이 아니면 빌드를 시작하기 전에 실패시킵니다.
- **버전 코드**는 Actions 실행 번호입니다. 같은 버전을 다시 돌려도 번호가 계속 커지므로 덮어써 설치할 때 항상 업데이트로 인식됩니다.
- **서버 주소**는 저장소 변수 `APP_URL`에서 받습니다. 운영 서버가 아직 없어서 비워 두었고, 이 경우 앱은 안내 화면만 보입니다.
- **푸시 알림 설정 파일**(`google-services.json`)은 비밀 값이 있을 때만 넣습니다. 없어도 빌드는 됩니다.

## 서명 키는 저장소에 둔 고정 debug 키로

릴리스 서명 키를 새로 만들어 보관하는 방법도 있었지만, 지금은 테스트 배포 단계입니다. 대신 debug 키를 저장소에 고정해 두고 모든 빌드를 그 키로 서명합니다. 이렇게 하면 두 가지를 얻습니다.

- 새 버전을 기존 앱 위에 그대로 설치할 수 있습니다. 빌드할 때마다 서명이 달라지면 지우고 다시 설치해야 합니다.
- 앱 안 구글 로그인에 등록하는 SHA-1 지문이 바뀌지 않습니다. 빌드 서버가 매번 새 debug 키를 만들면 지문이 달라져서 로그인이 깨집니다.

debug 키는 비밀 값이 아니라 표준 비밀번호(`android`)를 쓰는 키입니다. 그래서 구글 플레이 등록이나 일반 공개 배포에는 맞지 않고, 그 단계에서는 직접 만든 키로 바꿔야 합니다. 바꾸면 지문과 설치 호환이 달라지므로 문서에 그 사실도 적었습니다.

## README는 사용자 기준으로 다시 썼다

기존 README는 개발자용(저장소 구조, 문서 링크, 스택)이었습니다. 이 앱을 쓸 사람이 읽을 첫 화면으로 바꿨습니다. 앱 받기 링크, 이런 분께 맞는다는 소개, 할 수 있는 일, 설치 방법, 사용 방법, 제거, 개인정보, 꼭 알아둘 점 순서입니다. 개발자용 내용은 `docs/DEVELOPMENT.md`로 옮기고 README 끝에서 링크했습니다. 아직 만들지 않은 기능(정산관리 같은 것)은 완성된 것처럼 쓰지 않았습니다.

## 머지 전에는 시험할 수 없었다

워크플로의 `workflow_dispatch`(직접 실행)는 그 워크플로 파일이 기본 브랜치에 있어야 동작합니다. 그래서 머지하기 전에는 GitHub에서 한 번도 돌려 볼 수 없었습니다. 대신 PC에서 같은 명령으로 빌드해서 APK의 버전, 버전 코드, 서명 지문이 의도대로인지 확인했습니다. YAML 문법은 파서가 없어서 들여쓰기만 눈으로 봤습니다.

그리고 머지한 뒤 처음 돌리자 빌드 단계에서 실패했습니다.

```
./gradlew: Permission denied
```

원인은 간단했습니다. 윈도우에서 커밋한 `gradlew`에는 실행 권한이 없어서(파일 모드 100644) 리눅스 빌드 서버가 실행하지 못한 것입니다. 윈도우에서는 실행 권한이라는 개념이 없어서 PC 빌드에서는 드러날 수 없었습니다. 파일 모드를 100755로 바꾸고, 모드가 다시 풀려도 동작하도록 워크플로의 빌드 줄에 `chmod +x ./gradlew &&`도 넣었습니다. 두 번째 실행은 성공해서 릴리스에 6.5MB짜리 `HuyaShop.apk`가 올라갔습니다.

PC 빌드에서 한 가지 더 있었습니다. 래퍼가 `gradle-8.11.1-all` 배포판을 받다가 시간 초과가 났습니다. 이미 설치된 `-bin` 배포판으로 `--offline` 빌드해서 확인했고, 빌드 서버는 인터넷이 되므로 래퍼 그대로 두었습니다.

## 남은 것

- 폰에 설치해 실제로 열어 보는 확인은 아직 하지 않았습니다.
- 저장소가 비공개라서 내려받는 사람도 GitHub에 로그인해야 합니다. 로그인 없이 받게 하려면 저장소를 공개하거나 APK만 올리는 공개 저장소를 따로 두어야 하는데, 그 결정은 보류했습니다.
- 운영 서버가 생기면 `APP_URL`을 넣고 같은 워크플로를 다시 실행하면 새 버전이 나옵니다.
