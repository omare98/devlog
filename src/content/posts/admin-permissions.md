관리자 화면의 권한은 두 단계입니다. 먼저 **역할**을 만들고 메뉴별 허용 동작을 정한 뒤, **계정**에 역할을 지정합니다. 그런데 이 두 일이 서로 다른 화면에 있었습니다.

## 어디가 불편했나

- 역할 화면에서는 "이 역할을 누가 가졌나"를 볼 수 없었습니다.
- 계정 화면에서는 역할 이름만 보여서 "이 계정이 실제로 뭘 할 수 있나"를 알 수 없었습니다.
- 역할이 없으면 화면을 옮겨 만들고 돌아와야 했습니다.

## 먼저 메뉴를 정리했다

관리자 메뉴를 "계정관리·코드관리·권한관리"로 나누고, 역할과 권한 변경 이력은 권한관리의 탭으로 옮겼습니다. 기존 주소(`/roles` 등)는 새 주소로 보내는 리다이렉트를 남겨 즐겨찾기가 끊기지 않게 했습니다.

## 합의한 설계: 양쪽에서 같은 데이터를 본다

세 가지 안을 목업으로 비교해 "양쪽에서 같은 데이터를 보고 서로 연결"하는 안을 골랐습니다.

- **역할 쪽:** 권한표 아래에 "이 역할을 가진 계정" 체크 목록을 둡니다.
- **계정 쪽:** 역할마다 권한 요약을 보이고, 체크한 역할을 합친 "이 계정이 할 수 있는 일"을 미리 보여 줍니다. 역할이 없으면 권한관리로 가는 링크를 둡니다.
- **서버:** `PUT /api/roles/{id}/admins`를 더합니다. 계정별 지정과 같은 이력을 남깁니다.

## 서버에서 지킨 규칙

- 슈퍼 관리자가 목록에 하나라도 있으면 **아무것도 바꾸지 않고** 거부합니다(부분 적용 금지).
- 바뀐 것이 없으면 변경 이력을 남기지 않습니다.
- 합친 권한 미리보기는 서버에 묻지 않고 이미 받은 역할 목록으로 화면이 계산합니다.

## 배운 것

화면이 나뉜 문제는 화면을 합치는 것만이 답이 아니었습니다. 양쪽이 같은 데이터를 보여 주고 서로 오갈 수 있게만 해도 "두 번 일한다"는 느낌이 사라졌습니다.
