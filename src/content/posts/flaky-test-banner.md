배너 관리 화면의 테스트가 몇 번에 한 번씩만 실패했습니다. 이런 테스트는 재실행하면 지나가서 넘기기 쉽지만, 쌓이면 테스트 전체를 믿을 수 없게 됩니다.

## 추측하지 않고 원인부터

실패 메시지는 "알림 영역이 하나가 아니라 둘"이었습니다. 화면이 `role="status"` 영역을 하나만 가진다고 가정한 테스트였습니다.

원인은 드래그 앤 드롭 라이브러리(dnd-kit)가 접근성 안내용으로 `DndLiveRegion`을 **비동기로** 화면에 붙이는 것이었습니다. 어떤 실행에서는 테스트가 조회하기 전에 붙고, 어떤 실행에서는 후에 붙었습니다.

## 고친 방법

라이브러리 영역을 지울 수는 없어서, 테스트가 **우리 화면의 알림만** 보도록 바꿨습니다. `id`가 `DndLiveRegion`으로 시작하는 요소를 걸러 내는 작은 도우미(`rollingNotice()`)를 만들어 썼습니다.

```ts
const rollingNotice = () =>
  screen.getAllByRole('status').filter((el) => !el.id.startsWith('DndLiveRegion'))
```

## 배운 것

- 간헐 실패의 대부분은 **타이밍에 따라 달라지는 것**을 고정된 것으로 가정한 테스트입니다.
- 재실행으로 넘기지 말고 원인을 찾으면, 고친 뒤에는 같은 종류의 실패가 다시 나오지 않습니다.
