쿠폰 기능은 테스트를 전부 통과했는데, 개발 서버에서 사람이 직접 써 보자 문제가 줄줄이 나왔습니다. 하나같이 **기능은 있는데 사용자가 거기까지 가는 길이나 보이는 방법이 없는** 종류였습니다.

## 1. 쿠폰은 있는데 "쿠폰이 없습니다"

코드 입력 방식 쿠폰을 만들어 두고 결제 화면으로 갔더니 "사용할 수 있는 쿠폰이 없습니다."만 나왔습니다. 쿠폰을 만들었다고 고객에게 생기는 것이 아닙니다. 고객이 **내 쿠폰함에서 코드를 등록**해야 합니다. 관리자 목록에는 발급 `0 / 10`이라고 정직하게 나와 있었습니다.

문제는 두 겹이었습니다.

- **결제 화면에는 코드를 어디서 등록하는지 안내가 없었습니다.** 쿠폰이 하나도 없을 때 "쿠폰 코드가 있나요? 내 쿠폰함에서 등록하기" 링크를 넣었습니다.
- **PC에는 쿠폰함으로 들어가는 길 자체가 없었습니다.** 링크가 모바일 하단 "계정" 화면에만 있고 PC 헤더 메뉴에는 없었습니다. 주소를 직접 입력해야만 갈 수 있었습니다. 헤더의 "내 주문" 옆에 "내 쿠폰"을 추가했습니다.

이 둘을 처음에는 제가 틀리게 안내하기도 했습니다. "내 계정에서 쿠폰 메뉴로 들어가세요"라고 했는데, 그건 모바일 기준 설명이었고 PC 화면에는 그 메뉴가 없었습니다. 사용자가 "내 쿠폰함 없는데"라고 하고서야 갭이 드러났습니다. 코드를 읽어서 안다고 생각한 경로가 실제 화면에는 없을 수 있습니다.

## 2. 총액이 상품 금액보다 작은데 이유가 없다

쿠폰을 쓴 주문을 관리자 화면에서 열었더니 상품 금액 34,500, 총액 24,500인데 **왜 10,000이 빠졌는지 보이는 곳이 없었습니다.** 서버 계산은 맞았습니다. 응답에는 `couponDiscount`와 `couponName`이 이미 들어 있었는데, 관리자 화면의 주문 타입에 그 필드가 없어서 받고도 그리지 않았던 것입니다. 서버는 값을 주고 화면은 모르는 필드를 조용히 무시하니 테스트도 잡지 못했습니다.

"결제 금액" 카드의 배송비 아래에 "쿠폰 할인 (쿠폰 이름) -10,000 IDR" 줄을 추가했습니다. 쿠폰을 쓰지 않은 주문에는 줄이 없습니다.

## 3. 달력이 모달 밖으로 잘린다

쿠폰 등록 창의 사용 시작일을 누르면 달력이 열리다 말고 잘렸습니다. 모달 본문은 스크롤 영역(`overflow-y: auto`)이라서, 그 안에서 `absolute`로 띄운 팝업이 영역 밖으로 나가는 순간 잘립니다. 달력을 `position: fixed`로 화면 기준에 놓고 버튼 위치에서 계산하도록 바꿨습니다. 아래 공간이 모자라면 버튼 위로 올라가고, 좌우도 화면 밖으로 나가지 않습니다. 스크롤하거나 창 크기를 바꾸면 위치를 다시 계산합니다. 이 달력을 쓰는 다른 화면(상품 등록, 주문 목록 필터 등)도 같이 고쳐졌습니다.

## 4. 작은 것들

- **"자동 생성" 버튼 위치**: 입력칸 아래 안내 문구까지 포함해 버튼이 아래쪽에 맞춰져 있었습니다. 안내 문구를 줄 밖으로 빼서 버튼이 입력칸과 같은 높이에 놓이게 했습니다.
- **쿠폰 정보 창**: 목록에서 쿠폰 이름을 누르면 읽기 전용 정보 창(혜택, 조건, 기간, 발급 현황, 4개 언어 이름)이 열립니다. 행 전체가 아니라 이름만 눌리는 것은 상품 이름 팝업과 같은 방식이라서입니다. 한번은 "누르면 안 열린다"는 말을 들었는데, 코드 문제가 아니라 제가 작업 폴더를 정보 창이 없는 다른 브랜치로 돌려 둔 탓이었습니다. 개발 서버는 체크아웃된 브랜치를 그대로 보여 줍니다.

## 정리

자동 테스트는 "코드가 의도한 대로 동작하는가"를 확인하고, 직접 써 보는 것은 "사람이 이 기능에 도달할 수 있는가"를 확인합니다. 둘은 다른 질문이라 한쪽이 다른 쪽을 대신하지 못했습니다. 새 기능을 만들면 마지막에 **처음 쓰는 사람처럼 PC와 모바일에서 끝까지** 한 번씩 눌러 보는 시간을 꼭 넣기로 했습니다.
