서버가 "바뀐 가격이 0 이하가 되는 상품이 있습니다"라고 한국어 문장을 내려보내면, 영어·중국어·인도네시아어 화면에서는 그 문장을 그대로 보여 줄 수밖에 없습니다. 그래서 화면에 보일 수 있는 오류는 **문장이 아니라 세부 코드와 값**으로 내려보내기로 했습니다.

## 응답 모양

```json
{
  "code": "INVALID_CATALOG",
  "message": "바뀐 가격이 0 이하가 되는 상품이 있습니다. 상품 번호: 7",
  "detail": { "code": "CURRENCY_CONVERSION_RESULT_NOT_POSITIVE", "params": { "productId": 7 } }
}
```

- `code`는 큰 분류이고, 화면마다 이 코드의 번역을 가집니다.
- `message`는 한국어 설명입니다. 로그용이고 화면에는 보이지 않습니다.
- `detail`이 있으면 화면이 세부 코드의 번역에 값(`productId`)을 끼워 사용자의 언어로 보여 줍니다.

## 번역은 원본 한 곳에서

세부 코드의 번역은 서버의 `error-details/{ko,en,zh,id}.json` 한 곳에 두고, 스크립트로 관리자와 쇼핑몰 번역 파일에 복사합니다. 손으로 두 군데를 고치면 어긋나기 때문에 복사본은 직접 고치지 않는 규칙입니다.

## 규칙을 사람이 아니라 테스트가 지킨다

- **한글 리터럴 검사:** 지켜야 할 예외 클래스를 한글 문자열로 만드는 코드가 있으면 테스트가 실패합니다.
- **번역 완결 검사:** 모든 세부 코드에 4개 언어 번역이 있는지, `{{값}}` 자리표시가 서버가 보내는 값 이름과 같은지, 화면 번역 파일이 원본과 같은지 확인합니다.

새 오류를 하나 만들 때 번역을 빠뜨리면 빌드가 막히므로, "나중에 번역하지"가 생기지 않습니다.

## 배운 것

오류 메시지는 코드의 일부가 아니라 **화면의 일부**입니다. 서버는 "무슨 일이 일어났는지"만 말하고, 어떻게 말할지는 화면이 정하게 하자 다국어가 쉬워졌습니다.
