주문 상태("결제 완료", "배송 중" 같은 이름)를 화면 번역 파일에 두면, 이름 하나 고치려고 코드를 고치고 배포해야 합니다. 그래서 화면에 이름이 보이는 값은 DB의 `codes` 표에 **코드**로 두고, 관리자가 코드관리 화면에서 4개 언어(ko/en/zh/id) 이름을 직접 고치게 했습니다.

## 시스템 코드와 사용자 코드

| 구분 | 코드 값 | 이름 | 추가·삭제 |
|---|---|---|---|
| 시스템 코드 | 프로그램이 정한다(상태 값). 바꾸거나 지울 수 없다. | 관리자가 수정할 수 있다. | 개발이 마이그레이션으로 추가한다. |
| 사용자 코드 | 관리자가 정한다. | 관리자가 수정할 수 있다. | 관리자 화면에서 한다. |

주문 상태가 바뀌는 로직은 코드의 값(`PAID` 등)에 묶여 있어서, 관리자가 값을 바꾸거나 지울 수 있으면 프로그램이 깨집니다. 그래서 **이름은 누구나 수정, 값은 시스템 코드면 고정**으로 나눴습니다.

## 사용자 코드를 둘 수 있는 곳은 한정

처음에는 취소 사유(`CANCEL_REASON`)만 사용자 코드를 허용합니다. 나머지 그룹은 프로그램이 상태 값으로 쓰기 때문입니다. 허용 여부는 코드 그룹(`CodeGroup`)이 정합니다.

## 안전하게 지우기

사용자 코드는 지울 수 있지만, **어떤 주문이 쓰는 코드는 지울 수 없습니다**(409). 사용처는 `CodeUsage` 인터페이스를 구현한 클래스(주문 쪽 구현 등)가 알려 주므로, 새 사용처가 생기면 구현만 하나 더하면 됩니다.

## 취소 사유가 첫 사용처

관리자가 주문을 취소할 때 사유 코드를 고르고 내용을 적습니다. 사유가 "기타"이면 내용이 필수입니다. 주문에는 코드와 내용이 따로 저장되고, 화면은 보는 사람의 언어로 "사유 이름 — 내용"을 보여 줍니다. 코드가 없는 옛 주문은 옛 글을 그대로 보여 주고 옛 데이터는 바꾸지 않았습니다.

## 빠뜨리지 않게 테스트로

새 상태 값을 만들고 코드 등록을 빠뜨리면 `CodeRegistrationTest`(상태 값과 DB 시스템 코드 일치)가 실패합니다. 화면 쪽은 목록이 없거나 이름이 비어 있으면 코드 값을 그대로 보여 줘서 화면이 비지 않습니다.

## 배운 것

"이름을 고칠 수 있게" 하려면 **무엇이 값이고 무엇이 이름인지**를 먼저 나눠야 합니다. 그 구분이 있으면 관리자에게 맡길 수 있는 범위가 분명해집니다.
