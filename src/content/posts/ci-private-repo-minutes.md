PR을 올렸더니 CI가 3초 만에 실패했고, 뒤의 백엔드·프런트엔드 검사는 건너뛰어졌습니다. 테스트가 틀린 것이 아니었습니다. 작업이 아예 시작되지 않았습니다.

## 원인

실패한 작업의 안내 문구는 "최근 계정 결제가 실패했거나 지출 한도를 늘려야 한다"였습니다. 비공개 저장소는 GitHub Actions의 무료 사용량이 한정되어 있고, 넘으면 분 단위로 유료입니다. 이 저장소는 비공개라서 이번 달 무료 분이 소진됐거나 계정에 결제 문제가 있는 것으로 보였습니다. 어느 쪽인지는 설정의 사용량 화면을 봐야 정확히 알 수 있습니다.

## 공개로 바꾸면 되지만

공개 저장소는 GitHub 호스팅 실행 환경이 무료입니다. 그런데 CI 때문에 공개로 바꾸는 건 하지 않기로 했습니다. 공개는 코드만이 아니라 커밋 기록 전체가 공개되는 일이라 되돌려도 이미 퍼진 내용은 회수할 수 없습니다. 비밀 값이 과거 커밋에 남아 있지는 않은지, 개인 정보나 사업 정책 문서가 괜찮은지부터 점검해야 합니다. 추가 결제가 생기는 선택도 하지 않기로 했습니다.

## 실행 기록으로 줄일 곳 찾기

최근 실행 기록의 소요 시간을 보면, PR에서 도는 CI가 대개 7~12분이었고 `main`에 머지한 직후 도는 실행이 비슷한 시간(대개 8~14분)을 한 번 더 썼습니다. 같은 내용을 PR에서 이미 검사하는데 머지 직후에 전체를 한 번 더 도는 것이 사용량의 절반쯤이었습니다.

그래서 세 가지를 바꿨습니다.

- `main` 푸시 실행을 없앴습니다. PR 검사는 `main`과 합친 결과로 돌기 때문에 같은 내용을 이미 확인합니다. 머지 뒤에 한 번 더 확인하고 싶으면 Actions 탭에서 직접 실행할 수 있게 `workflow_dispatch`를 남겼습니다.
- 문서만 바뀐 PR(`*.md`, `docs/**`)은 CI를 돌리지 않습니다.
- 작업마다 시간 상한을 뒀습니다(변경 감지 5분, 백엔드 30분, 프런트 15분). 멈춘 실행이 무료 분을 먹지 않게 하려는 것입니다.

바뀐 파일을 보고 필요한 모듈만 검사하는 규칙과 같은 PR의 이전 실행 취소는 그대로입니다.

## 잃는 것

머지 직후 자동으로 한 번 더 확인하던 안전망이 없어졌습니다. 서로 다른 PR이 합쳐진 결과를 자동으로 보지 않습니다. 이 저장소는 비공개 무료 플랜이라 브랜치 보호(필수 검사 지정)를 쓸 수 없어서 다른 영향은 없습니다. 필요해지면 푸시 트리거를 다시 켜면 됩니다.

## 그동안은 어떻게 했나

CI가 돌지 않는 동안에는 제 PC에서 전체 백엔드 테스트와 프런트 테스트, 타입 검사, 린트, 빌드를 직접 돌려 확인하고 머지했습니다. CI가 시작되지 않은 것을 "통과"로 읽으면 안 됩니다. 어느 검사를 어디서 돌렸는지 PR에 적어 두었습니다.

## 배운 것

- 빨간 X가 코드 문제라고 단정하지 말고 작업이 시작됐는지부터 봅니다. 이번에는 작업이 2~3초 만에 끝났고 로그가 아예 없었습니다.
- 줄이는 대상은 측정으로 찾습니다. 머지 직후 실행이 사용량의 절반이라는 건 실행 기록을 보고서야 알았습니다.
- 줄일 때는 무엇을 잃는지를 같이 적어 둡니다.
